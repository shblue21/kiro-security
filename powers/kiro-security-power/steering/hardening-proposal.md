# Hardening proposal
For a Fast scan, call `security_create_hardening_proposal` after reviewing validated findings and systemic patterns. For a model-tail hardening assignment, use only the supplied canonical threat model and completed finding proofs. Cluster opportunities by violated invariant, trust boundary, control owner, dangerous capability, or repeated preventive control—not merely CWE, title, or severity. Distinguish observed facts, inference, and proposed design; give materially different options with residual risk, performance, reliability, operational, compatibility, rollout, and rollback tradeoffs. Prefer local remediation when the evidence does not justify architectural change, and never claim that a proposal fixes a finding before implementation and revalidation. Completed Standard/Diff/Deep scans already materialize an immutable tail hardening portfolio; read that artifact instead of regenerating it.
