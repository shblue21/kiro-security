# Threat model
Call `security_create_threat_model` for the selected scope. Ground the model in the repository's real product and runtime surfaces, distinguishing them from tests, examples, documentation, generated code, and developer-only tooling. Identify protected assets, actors, attacker/operator/developer-controlled inputs, entry points, trust boundaries, privileged operations, assumptions, existing controls, and material unknowns with concrete repository evidence. Describe realistic and out-of-scope attacker stories and calibrate which vulnerability classes matter in this product context. Do not turn threat modeling into finding discovery, treat a repository hint as proof, or invent deployment facts that the snapshot does not establish.
