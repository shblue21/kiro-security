# Finding remediation
Use `security_create_remediation` when guidance alone is requested. For an actual fix, retrieve the current finding, develop the smallest repository-native source-and-test diff, then call `security_prepare_remediation_patch`. Review the exact patch before separately calling `security_apply_remediation_patch`; the engine rejects drift, traversal, symlinks, binary patches, renames, and mode changes. Run the focused and existing repository checks through Kiro Agent, then submit their bounded results with `security_verify_remediation_patch`. Never report `verified` when the original issue still reproduces, legitimate behavior was not preserved, a check failed, or a proof gap remains.
